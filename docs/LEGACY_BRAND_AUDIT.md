# 旧品牌审计

```sh
bun run check:legacy-brand
node scripts/audit-legacy-brand.mjs --json
```

审计已接入根 `lint`。退出码 0 表示所有命中均有精确批准；新增命中、未读到的文件、失效或格式错误的例外均失败。脚本只读，不调用 Git，不自动批准命中。

## 批准单位

`docs/legacy-brand-exceptions.json` 是唯一清单。每项包含：

- `kind`：`content` 或 `path`。
- `path`：完整相对路径，不支持 glob 或目录豁免。
- `line`：内容命中的完整原始行，含空格；路径命中不填此字段。
- `count`：该完整行在该文件中允许出现的精确次数。移动行号不影响批准，修改行内容、复制一行或复制到另一个文件都会失败。
- `category`、`reason`、`owner`、`exitCondition`：用途、理由、负责人角色与退出条件。

审计者逐项检查运行时代码是否仅为迁移读取、旧协议拒绝、用户明确要求的旧深链接收/系统注册或必要归属记录；当前正常写入、默认配置与新生成链接不能用兼容理由批准。旧深链别名只用于接收，所有新链接仍使用 Yuri。测试例外必须说明保护的可观察行为。源代码删去例外后同步删除清单项，否则报 `STALE`。没有自动 baseline/update 命令。

## 范围

脚本扫描仓库内文本与文件/目录名称，包含隐藏源文件、迁移模块和测试。匹配规则由脚本固定，覆盖旧产品名、上游账号及作者姓名的指定变体，大小写不敏感。

依赖、VCS 内部文件、本地事项/工作区/凭据、构建输出与缓存不属于源代码审计。排除项在脚本的 `excludedNames` / `excludedRoots` / `excluded` 中显式列出；没有迁移目录豁免。移动原生工程复制的 `public` Web 产物按两个准确路径排除，源 UI 仍扫描。

清单本身是批准记录的序列化载体，仅此准确文件不递归扫描内容。所有清单项仍须通过格式、精确命中与计数校验。符号链接扫描路径但不跟随目标，避免进入仓库外用户数据；含 NUL 的二进制跳过内容。图片、安装包及解包产物另做视觉/产物审计，不能用本命令声称已验证。

## 收口

并行迁移实现结束后运行审计。对 `UNAPPROVED`，优先修复正常产品路径中的旧身份；仅审核通过的兼容读取和必要历史/法律记录可增加精确清单项。对 `STALE`，检查对应实现变更后删除或收紧批准。运行 `deploy/update-service/test/brand-audit.test.mjs` 验证新命中、重复行、隐藏文件、路径与过期批准的失败行为。
