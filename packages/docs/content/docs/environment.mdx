# Override the host's startup configuration

Environment values apply to the process that reads them. Setting a variable on your phone or in an unrelated terminal does not reconfigure the connected Yuri host. Restart the intended process after changing its startup environment.

## Change how Yuri is reached or stored

| Variable | Purpose |
| --- | --- |
| `YURI_HOST` | The web host's bind address. A wider bind changes network reachability. |
| `YURI_UI_PASSWORD` | Browser UI authentication password. |
| `YURI_API_ONLY` | `true` or `1` keeps API service without serving the browser UI. |
| `YURI_DATA_DIR` | Override Yuri's data directory, normally `~/.config/yuri`. |

Changing the data directory selects another storage location; it does not migrate the old contents. Set host access and authentication together when widening the bind address.

## Select the execution environment

| Variable | Purpose |
| --- | --- |
| `OPENCODE_HOST` | An HTTP(S) origin with an explicit port; no path, query or fragment. Takes precedence over `OPENCODE_PORT`. |
| `OPENCODE_PORT` | Explicit OpenCode port selection. |
| `OPENCODE_SKIP_START` | `true` selects the no-managed-start path. |
| `OPENCODE_BINARY` | Explicit OpenCode executable selection. |
| `YURI_TERMINAL_SHELL` | Shell executable for Yuri terminal sessions. |

Use the [host guide](/opencode-server/) for an external-runtime example. When a startup service captures environment variables, changing your current shell alone will not change that already-installed service.

This is an operator reference, not a list of every internal build or debug variable. Prefer the visible Settings controls for model, speech and appearance configuration.
