# Pair a client with the right host

Start on the computer whose projects you want to access. In its Yuri **Settings → Remote Instances**, use **Add a device** in the connection section. This screen requires the host's client-management capability; it is not a VS Code setting.

## Choose the reach before making the code

The pairing dialog offers local, LAN and Relay choices according to host availability. Local is for the same computer; LAN requires a reachable network address; Relay is for access beyond that network. Check the offered fallback option if you want both available routes.

Name the device and create the code. On a phone, scan it from the connection screen or paste the pairing link. In the desktop app, use **Import link** in Remote Instances. Redeeming the code creates the saved client connection; the code is single-use and expires.

## Confirm the destination, not just the connection

Open a known project after connecting. A successful connection to the wrong host can look like missing sessions. The native phone app manages saved hosts under **Settings → Switch instance**; it does not expose the desktop's entire Remote Instances editor.

To remove access, revoke the client on the issuing host. Removing a saved connection locally and revoking its host credential are different actions.

## A terminal-managed pairing

On the host, `yuri connect-url --port 3000 --qr` creates a direct-capable link for that instance. `yuri connect-url --relay --qr` instead creates a Relay-only link and requires a running, Relay-enabled host; it does not start one. Use the command's `--help` for address and binding options. Browsers can use the reachable web address and its login flow.
