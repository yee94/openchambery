# 找出失败发生在哪一层

不要同时修改多项设置。先记下设备、当前主机、应用版本，以及失败的具体操作。

## 你仍然能打开什么？

| 观察到的现象 | 排查方向 |
| --- | --- |
| 主机本地可用，另一台设备连不上 | [连接排查](/zh-cn/troubleshooting/remote-access/)。 |
| Yuri 能打开，会话无法使用执行服务 | [OpenCode 就绪状态](/zh-cn/troubleshooting/opencode-connection/)。 |
| 仓库操作或独立工作目录创建失败 | [Git 与 Worktree 检查](/zh-cn/troubleshooting/worktrees-git/)。 |
| 只有公开网址失败 | 对比直连结果和[代理清单](/zh-cn/reverse-proxy/)。 |

## 收集最少但有用的依据

CLI 主机查看 `yuri status` 与 `yuri logs`；桌面或手机记录「关于」中的组件版本和可见错误。使用运行实例实际提供的地址，桌面端口不一定是 `3000`。

重启前保留失败请求和未发送草稿。每做一次针对性调整，就重复同一操作，确认是否改善。反馈问题时附上预期结果和复现步骤，去掉凭据与配对链接。
