# 通过 HTTPS 发布已运行的主机

这是基础设施配置，不是 Yuri 设置页面。先确认主机可以直接访问，记下实际地址和端口，再添加代理。

## 保持连接行为完整

一致地转发应用与 API 路径，包括认证路径；保留公开 origin 所需的主机和转发协议信息。支持 WebSocket 升级和长连接，不要把 SSE 缓冲成请求结束后才一次性出现的响应。

长连接路径包括 `/api/event/ws`、`/api/global/event/ws`、`/api/terminal/ws`、`/api/yuri/events` 和 `/api/notifications/stream`。这不是完整允许列表，语音等能力还会使用自己的端点。

按实际附件设置上传大小限制，按交互会话设置空闲超时。主机和代理的压缩应一起考虑，不要直接叠加无关示例中的假设。

## 测试四个真实操作

1. 通过公开 HTTPS 地址登录并重新加载。
2. 发送请求，确认任务进行中就能看到进展。
3. 打开终端，再发送一个有代表性的附件。
4. 短暂断开客户端网络，检查能否重新连接。

直连成功、代理失败时，检查代理的上游状态、升级处理、缓冲和大小限制。两者都失败时，先回到[主机排查](/zh-cn/troubleshooting/)，不要继续修改代理。
