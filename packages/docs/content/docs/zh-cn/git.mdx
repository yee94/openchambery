# 从 Diff 到确认后的提交

桌面端从右侧栏的 **Git** 标签进入，先确认仓库和分支确实是这次要修改的对象。

## 决定哪些改动进入提交

打开变化的文件检查 Diff，只暂存需要的部分，填写提交信息后提交。生成按钮可以起草提交信息，使用前仍需检查措辞。

Git 视图还提供同步、历史和 stash 操作。切换分支或恢复 stash 前，先看清当前分支与工作区状态。

## 把 GitHub 背景交给会话

在非 VS Code 界面，通过 **设置 → Git** 连接账号。从输入框附件菜单选择已有 Issue 或 PR，作为任务上下文；连接 GitHub 后，创建 Worktree 时也可以选择对应事项。

侧栏的 PR 状态可以跳转 GitHub。创建、更新和合并 PR 请在 GitHub 完成，或明确交给具备对应能力的 Agent。当前 Yuri Git 界面没有 PR 管理标签页。

提交作者配置见 [Git 身份](/zh-cn/git-identities/)，隔离工作目录见 [Worktree](/zh-cn/worktrees/)。
