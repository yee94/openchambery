# 在工作空间中使用 Magpie

Magpie 管理模型访问，并通过网关提供服务。Yuri 使用当前 OpenCode 运行环境中的模型，同时支持读取 Magpie 聚合用量，以及从桌面端向另一台主机显式传输 Magpie 配置。这是几条独立的连接，配置好其中一项，不会自动完成其余配置。

## 先接入准备使用的模型

在运行执行服务的电脑上，先在 Magpie 配好提供商或订阅，再通过 Magpie 的 Agent 配置连接 OpenCode。从当前模型目录选择目标模型，不要照抄示例中的模型 ID。这一步可以参考 [Magpie 入门说明](https://usemagpie.ai/docs/start)。

回到 Yuri 检查提供商和模型列表，在会话中选定模型，发送一个小请求验证。仅仅看到用量卡片，并不能证明该会话正在使用 Magpie 网关。

Magpie 还可以加载提供商或认证插件，把它们提供的模型暴露到网关。此类插件应当 **在 Magpie 中安装并登录**，见其[插件指南](https://usemagpie.ai/docs/plugins)。Yuri 的 **设置 → 插件** 管理的是 OpenCode 自身扩展，不是 Magpie 插件目录；不能因为 Magpie 支持某个包，就认定它兼容当前 OpenCode 版本。

## 看清网关背后的账户用量

打开 **设置 → 用量**，找到 **Magpie** 分组。Yuri 会发现与当前主机同机运行的 Magpie，也能识别当前 OpenCode 服务配置的网关。它不会去扫描手机或浏览器所在电脑上的另一份安装。

需要连接其他网关时，展开 **连接其他 Magpie**，填写 HTTP(S) 网关地址并保存。地址不能嵌入凭据、查询参数或片段。远程用量访问需要密钥时，由主机管理员配置 `YURI_MAGPIE_API_KEY`，Magpie 网关也需要允许该密钥读取用量。

Magpie 提供相应数据时，可以看到分账户用量、额度窗口、余额和重置时间。使用用量页的标题栏显示控制，选择需要常看的账户；刷新会请求较新的读数。出现错误或过期标记时，不要把保留的旧值当成刚刚读取成功，更不能理解为零用量或无限额度。

## 把配置带到另一台主机

在桌面端 **设置 → 远程实例** 中，打开目标连接可用的配置同步操作。向导可以通过支持的 SSH、直连和 Relay 连接推送或拉取；SSH 入口要求已就绪的托管连接，外部服务条目不提供该操作。

1. 选择方向，确认哪台电脑是来源。
2. 等待发现结果。只有来源端存在可发现的 CLI 和可传输数据时，才会显示单独的 **Magpie** 选项。仅残留配置文件、没有安装 CLI，并不满足条件。
3. 主动勾选 Magpie；它默认不选。检查预览后再执行。
4. 阅读完成结果，并在目标端实际测试一个模型。

传输使用 Magpie 自身的备份与恢复能力，包含配置、API 密钥、配置档案、模型分配、资料库和可移植插件声明。当前主机还可以传输已识别的插件登录与支持的已保存 Codex 账号；其他订阅登录可能仍需在目标端完成。需要传输授权时，两端都应使用当前版本。

目标缺少 CLI 时，只有明确执行已勾选的 Magpie 传输才会自动安装。预览和普通 OpenCode 配置同步不会安装它。传输失败可能已有部分配置生效，重试前先查看结果。该流程是主动传输，不是持续自动同步，发起向导仅在桌面端提供。

## 找出缺少的是哪条连接

| 现象 | 接下来检查 |
| --- | --- |
| 有用量，却找不到模型 | Magpie 的 OpenCode 配置，以及 Yuri 当前运行环境与模型目录。 |
| 模型能用，用量不可用 | 网关身份、用量权限、主机地址和发现错误。 |
| 同步向导没有 Magpie 选项 | 来源方向、CLI 是否被发现，以及是否存在可传输数据。 |
| 同步结果提示需要登录 | 在目标端 Magpie 登录对应账户，再测试模型。 |

普通账户显示见[用量指南](/zh-cn/usage/)；主机连接本身见 [SSH 访问](/zh-cn/remote-instances/)和[设备配对](/zh-cn/connect-devices/)。
