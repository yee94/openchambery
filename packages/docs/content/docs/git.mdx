# Turn a diff into a reviewed commit

The Git tab in the right sidebar is the starting point on desktop. Check that it shows the repository and branch you intended to change.

## Choose what belongs in the commit

Open changed files to inspect their diffs. Stage only the intended changes, write a commit message, then commit. The generation control can draft the message; review the wording before using it.

The Git view also exposes synchronization, history and stash actions. Read the current branch and working-tree state before switching branches or restoring a stash.

## Bring GitHub context into the request

Outside VS Code, connect your account through **Settings → Git**. Use the composer's attachment menu to select an existing issue or pull request as context. The worktree creation flow can also start from a connected GitHub item.

PR status in the session sidebar can take you to GitHub. Create, update or merge the pull request there, or explicitly ask an appropriately configured Agent to do it. The current Yuri Git interface does not expose a PR-management tab.

For author identity, see [Git profiles](/git-identities/). For an isolated checkout, use [worktrees](/worktrees/).
