# Find your way around Yuri

Think of Yuri as a workspace on a particular computer. Your desktop window, phone and browser are ways to reach it. The host you select determines which files, conversations and assistants are available.

## Where are you starting?

| Your situation | Start here |
| --- | --- |
| You have not run Yuri yet | [Choose an installation](/install/), then [send a first request](/quickstart/). |
| Your work is already running on another computer | [Pair with that host](/connect-devices/), or use the desktop [SSH connection](/remote-instances/). |
| You want a contact to coordinate work | [Set up an assistant](/assistants/). |
| You want work to happen later | [Create a schedule](/scheduled-tasks/). |

## Two places to have a conversation

**Project sessions** expose the work itself: messages, tool activity and file changes. Choose a project when the request concerns files in a particular directory.

**Assistants** provide an ongoing contact conversation. They can hand work to sessions and return cards you can open. See the [assistant guide](/assistants/) for the distinction.

## Once work is underway

Read a result on your [phone](/mobile/), [speak a follow-up](/voice/), or [inspect the changes](/git/) before committing them. A [goal](/session-goals/) can keep a session pursuing an explicit outcome beyond one reply.

The host must remain available for remote access and scheduled execution. If something disappears after switching connections, check the host first. [Troubleshooting](/troubleshooting/) starts from what you can still access.
