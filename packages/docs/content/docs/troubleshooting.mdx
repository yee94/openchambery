# Locate the failing layer

Avoid changing several settings at once. First note the device, selected host, app version and exact action that failed.

## What can you still open?

| Observation | Follow this path |
| --- | --- |
| The host works locally but another device cannot reach it | [Connection troubleshooting](/troubleshooting/remote-access/). |
| Yuri loads, but a session cannot use its execution service | [OpenCode readiness](/troubleshooting/opencode-connection/). |
| A repository operation or isolated checkout fails | [Git and worktree checks](/troubleshooting/worktrees-git/). |
| Only the public URL fails | Compare direct access with the [proxy checklist](/reverse-proxy/). |

## Collect the smallest useful evidence

For a CLI host, inspect `yuri status` and `yuri logs`. For desktop or mobile, record the component versions shown in About and the visible error. Use the actual address from the running instance; desktop ports need not be `3000`.

Preserve the failing request and unsent draft before restarting. After one targeted change, repeat the same action so you can tell whether it helped. If reporting a problem, include the expected result and reproduction steps, with credentials and pairing links removed.
