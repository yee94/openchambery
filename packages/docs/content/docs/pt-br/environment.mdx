# Variáveis de ambiente

O Yuri lê estas variáveis na inicialização. Para serviços de inicialização, `yuri startup enable` salva por padrão um snapshot do ambiente atual, então execute de novo após mudar variáveis que o serviço deve usar.

## Servidor Yuri

### `YURI_HOST`

Endereço onde o servidor web do Yuri escuta. Use `0.0.0.0` para permitir acesso de outras máquinas.

### `YURI_UI_PASSWORD`

Senha da interface no navegador. Use quando expor fora do localhost ou por proxy reverso.

### `YURI_API_ONLY`

Inicia o Yuri em modo headless quando definido como `true` ou `1`. As rotas de API continuam disponíveis para clientes desktop e mobile, mas a UI do navegador não é servida.

### `YURI_DATA_DIR`

Altera o diretório de dados do Yuri. O padrão é `~/.config/yuri`.

### `YURI_COMPRESS_API`

Controla a compressão das respostas da API. `true` ou `1` ativa; `false` ou `0` desativa.

### `YURI_SKIP_API_COMPRESSION`

Desativa a compressão das respostas da API quando definido como `true` ou `1`. Tem prioridade sobre `YURI_COMPRESS_API`.

### `YURI_VERBOSE_REQUEST_LOGS`

Ativa logs HTTP detalhados quando definido como `true` ou `1`.

### `YURI_UPDATE_API_URL`

Altera o endpoint de verificação de atualizações. A maioria dos usuários deve deixar isso sem definir.

### `YURI_PACKAGE_MANAGER`

Força o gerenciador de pacotes usado em atualizações quando a detecção automática estiver errada.

## Servidor OpenCode

### `OPENCODE_HOST`

Conecta o Yuri a um servidor OpenCode existente. O valor deve ser um origin `http` ou `https` com porta explícita e sem path, query ou hash. `OPENCODE_HOST` tem prioridade sobre `OPENCODE_PORT`.

### `OPENCODE_PORT`

Define a porta do servidor OpenCode. Com OpenCode gerenciado, solicita essa porta; com `OPENCODE_SKIP_START=true`, conecta a um servidor externo nessa porta.

### `OPENCODE_SKIP_START`

Impede o Yuri de iniciar seu próprio servidor OpenCode quando definido como `true`.

### `YURI_OPENCODE_HOSTNAME`

Hostname do servidor OpenCode gerenciado pelo Yuri. O padrão é `127.0.0.1`.

### `OPENCODE_BINARY`

Caminho para o executável `opencode` que o Yuri deve usar.

### `OPENCODE_CONFIG`

Caminho para um arquivo de configuração específico do OpenCode.

### `OPENCODE_CONFIG_DIR`

Caminho para o diretório de configuração do OpenCode para agents, skills e descoberta de config.

### `OPENCODE_DATA_DIR`

Diretório de dados personalizado para o servidor OpenCode gerenciado.

### `OPENCODE_WSL_DISTRO`

Escolhe a distro WSL usada pela integração do OpenCode no Windows.

### `YURI_OPENCODE_WSL_DISTRO`

Alias específico do Yuri para escolher a distro WSL. `OPENCODE_WSL_DISTRO` tem prioridade quando ambas estão definidas.

### `OPENCODE_JWT_SECRET`

Segredo usado para assinar tokens de autenticação da UI. Em serviços persistentes, use um valor longo e aleatório.

## Terminal e Git

### `YURI_TERMINAL_SHELL`

Executável de shell usado nas sessões de terminal do Yuri.

### `YURI_GIT_BINARY`

Executável do Git usado pelos recursos Git do Yuri.

### `GIT_BINARY`

Override alternativo para o executável do Git. Para configuração específica do Yuri, prefira `YURI_GIT_BINARY`.

### `YURI_GIT_READ_CACHE_TTL_MS`

TTL, em milissegundos, para leituras de arquivos em cache baseadas em Git. Use `0` para desativar o cache durante depuração.

## Voz

### `OPENAI_API_KEY`

API key usada por recursos de voz do Yuri que chamam serviços compatíveis com OpenAI.

### `YURI_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Permite base URLs remotas compatíveis com OpenAI para recursos de voz quando definido como `true` ou `1`.

## Auxiliares de runtime

### `BUN_BINARY`

Executável do Bun que o Yuri deve usar ao iniciar processos daemon.

### `BUN_INSTALL`

Raiz da instalação do Bun. O Yuri usa isso para encontrar `bin/bun` ao iniciar daemons e atualizar.

### `VITE_OPENCODE_URL`

API base URL de build-time para a web app criada com Vite. A maioria dos usuários não deve usar isso no CLI ou desktop normal.
