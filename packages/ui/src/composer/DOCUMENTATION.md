# Composer module

`document.ts` owns normalized document ranges, validation, canonical materialization, and send-plan preparation. `extensions.ts` owns each reference strategy's payload validation, decoration shape, semantics, opaque-payload budget, canonical codec, and resource identity. `inline-attachment-sync.ts` owns inline attachment citation range find/strip helpers (images, documents, and VS Code files/selections) and Draft text+mention rebase when an attachment is removed; `input-store.removeDraftAttachment` clears those citations in the same revision so ChatInput does not hand-sync textarea text after remove. `reference-history.ts` owns bounded undo/redo snapshots for complete Composer reference documents. `use-composer-controller.ts` owns DraftKey-scoped local editing, store commits, history preview, submission capture/recovery, and post-commit resource deltas. Chat surfaces use the same controller and provide an explicit stable `DraftKey`; primary session and new-draft keys retain their existing durable encoding, while `surface` owners isolate secondary surfaces.

External, recovery, serialization, and materialization boundaries use full Composer validation. Browser-local edits use trusted normalization after the Draft parser or insertion validator has established typed payloads; it validates structural range and budget invariants without another opaque Paste Unicode scan. Native dictation and IME replacement ranges stay under browser ownership when reconciliation preserves their text and selection, except on Capacitor iOS primary chat: `OpenChamberComposer` presents a native `UITextView` overlay, ChatInput keeps the web textarea as a hidden document sink, and complete text (not marked-text ranges) crosses the bridge. Active IME composition suppresses imperative value, selection, and atomic-selection correction until `compositionend`, preventing iOS marked text from becoming a native blue selection. Reconciliation emits `requiresTextCorrection` from reference-range expansion, and imperative textarea correction runs only when this structural signal or caret mapping requires it. Unicode metrics use a shared bounded 400k UTF-16 LRU cache.

Add a reference kind by extending the durable draft union, then add its exhaustive strategy in `extensions.ts`. A strategy supplies its decoration and send contribution; ChatInput structurally merges the decoration into `HighlightRange` and keeps rendering, paste labels, and temporary attachment behavior locally. Chip-like mentions share one metric-safe visual contract in `inline-visual.ts`: `ComposerTriggerIconSpec` defines any trigger, icon, label, and optional suffix; `composerTriggerIconDisplay()` adds the durable em-space icon slot; `composerTriggerIconVisual()` maps the exact source display into the overlay; `composerTriggerIconText()` produces semantic delivery text. `COMPOSER_TRIGGER_ICON_SIZE_CLASS` owns the shared Composer and sent-message icon size for Session, Skill, Command, image, and attachment references. Session, Skill, Command, and attachment/image citations use the reserved em-space slot so a fixed 1em×1em icon well stays inside textarea metrics. `ComposerTriggerIconMark` centers that well in the trigger run with equal left/right inset (`COMPOSER_TRIGGER_ICON_LABEL_GAP`) so lead-in air and icon→label air stay balanced across `[`/`@`/`/`. Legacy compact source text (`[file]` without the slot) still renders, but may overflow a narrow trigger. Durable Skill references retain a slash-rule `skillName`, serialize as `[skill:name]`, and Durable Command references retain `commandName` plus a bounded `reference`, serialize as `[command:reference]`. Both use `mentionCommand` decoration, materialize from canonical tokens, and contribute no synthetic semantic; authored legacy slash skills retain their semantic delivery path.

Cross-input chip copy/paste is deliberate: ChatInput copy/cut writes semantic plain text through `stripComposerTriggerIconSlotsForPlainText` (no icon em-spaces) so pasting into another composer or a plain field does not leave a visible gap. Known slash tokens re-promote to reserved-slot chips on the next ChatInput edit. Send routing uses `parseSlashCommandInvocation` so a pasted or hand-typed `/\u2003name args` chip never treats the icon slot as the first argument separator.

On Capacitor iOS primary chat, `OpenChamberComposer` is a process-owned overlay (hide first, teardown later, do not rebuild across session and phone-page remounts). Native tab-bar adoption `warm`s the glass view hidden on the homepage so entering chat applies state onto an already-installed overlay instead of creating `UIGlassEffect` on that frame. ChatInput sets `:root.oc-native-ios-composer` in `useLayoutEffect` so the first chat paint skips the web composer chrome. Leaving chat conceals the overlay immediately (`hide`) so it is gone before the Projects underlay finishes appearing; `dismiss` waits for the remount window while listeners stay attached. Typing `/` or `@` opens a liquid-glass suggestion list above the card (same width as the card, 8pt gap, clamped below the mobile header). Trigger detection, fuzzy rank, and keyword match live in `packages/ui/src/lib/composer-autocomplete/` so a later language-server consumer can reuse them. Catalog fetch stays on the existing JS Command/Skill/File mention components; native only paints rows (WebView-rasterized sprite icons) and forwards tap or Return as `autocompleteAccept`. It paints a full-width collapsed pill (`+` inside, Send/Stop) and an expanded glass card whose footer matches web order (`+`, spacer, Agent, model, Send). Ready Send and Stop use the same inverted 24pt disc as web `SendCircleIcon` / `StopIcon` (idle Send stays a ghost arrow). Agent cycling and the agent/model pickers stay ChatInput-owned; native only forwards `cycleAgent` / `openAgent` / `openModel`. The native `UITextView` is uncontrolled while first responder or IME marked text is active; ChatInput echoes do not rewrite the field (`forceText` only for attach / clear / session). Trigger-icon chips are paint-only on native: JS publishes slim `chipRanges` (range + color, no icons) from the same highlight visuals as the web overlay; native colors the whole token with `--primary`, collapses the reserved U+2003 icon well visually (clear + kern; glyph stays in delivery text), unions those ranges with citations for whole-token delete, and never replaces glyphs or changes delivery text — sent messages still render through the web `ComposerTriggerIconMark` path. Chip attributes are not applied while IME marked text is active. Chrome-only native updates (`canSend`, scroll, abort) omit `chipRanges` and must not re-walk `textStorage` or re-rasterize model bitmaps; chip paint and model chrome bitmaps run only when those fields actually change. JS rasterizes missing chip icons once per icon+color and does not re-walk highlights on web/desktop. Native send is a fire-and-forget Web handoff (`send` → ChatInput `handlePrimaryAction` on the next macrotask): it does not wait on `update`/`forceText`, and Web owns queue, in-flight, and errors. The send event itself must not mark the draft as an echo; after Web clears the document, the empty write `forceText`s the `UITextView` even if a leftover echo flag is still set. Echoed keystrokes skip the Capacitor bridge unless chrome actually changed, and those diffs omit preview/icon bytes. Cancelled back `reveal` only `show()`s the existing overlay — it does not `present(lastState)` over a live field. The expanded card paints a horizontal attachment preview strip (40pt image thumbs and file chips, each with a remove control) from `attachmentPreviews`; `removeAttachment` calls the same store sink as the web list so citations clear in the same revision. JS also sends `citationRanges` so a backspace/delete that touches `[filename]` expands to the whole token; ChatInput then runs `reconcileComposerAttachmentTextDeletion` so deleting the citation text drops the attachment. The field still shows source text (`[\u2003filename]`) — it does not paint Web `ComposerTriggerIconMark` chips (that would be a separate TextKit overlay). IME marked text skips both the native range expand and JS reconcile. Return sends or queues and does not insert a newline unless IME marked text is confirming. While a turn can abort, Stop stays on the card; queue Send sits above it only when the card is expanded. `+` opens a `UIMenu` above the plus (photos first, then files) without resigning first responder. Photos use `PHPickerViewController`; files use `UIDocumentPickerViewController`. System pickers may hide the keyboard once; the card stays expanded and focus returns when they close. `filesPicked` (base64, 32 MiB cap) is forwarded so ChatInput can attach `File` objects — it must not open the disabled web attach sheet, because that is outside the iOS user gesture. The model chip paints name in medium 11pt and the thinking suffix in regular muted 11pt, both as bitmaps (`rasterModelChrome`) so a session switch on the process-owned overlay cannot keep the previous `UILabel` glyphs. JS republishes name + thinking with the icon whenever model identity changes. Expand/collapse snaps without footer layout animation so the model/agent labels do not slide. `--oc-native-composer-height` is the collapsed occupancy only so Changes / TODO / queue stay docked just above the pill while typing; accessory height is `--oc-native-composer-accessory`. The queue card hides its composer-overlap tail and uses matching top/bottom padding because the native pill does not cover that spacer. Those rows fade with `--oc-native-composer-dock` (distance from the live edge — the parked send when a reply is reserved, otherwise `scrollHeight`; hidden until that edge, fade-out over the first ~40px leaving) instead of composer-swap rest or translating away, and they have no page-background veil. Scroll-to-bottom is a circular liquid-glass control above Send (`scrollToBottom`) that appears after ~80px of upward travel from that same edge, returns to the parked hole without dropping it, and is excluded from published occupancy so the strip does not jump; the WebView control is hidden. Keyboard hide closes the native keyboard session (so a leftover `changeFrame` cannot keep the overlay raised), re-pins to the window home-indicator inset, collapses the card, blurs the native field, and re-reports that collapsed height. The web keyboard hide path still unwinds leftover `--oc-kb-layout` while skipping composer FLIP.

Resource owners receive `ComposerResourceDelta` identities after successful local commits. Image strategies return `{ type: 'attachment', attachmentRefID }`; Session, Paste, Skill, and Command strategies return no resource. Store hydration and DraftKey switches establish state without a local resource delta. Atomic Composer reference deletion owns whitespace normalization and records before/after snapshots containing text, every reference kind, mentions, and selection. Browser undo/redo restores these snapshots only when its current document matches the recorded boundary, preserving Paste payloads and all Session/Skill/Command semantics together. Sent-message Session, Skill, Command, and citation references reuse the trigger/icon/label/suffix reserved run (`trigger` + em-space, equal left/right inset — same as `ComposerTriggerIconMark`) so the icon cannot bleed into the first label letter. Slash/skill/command insert via ChatInput sets `padLeadingDocumentEdge: false` so document-start chips keep a trailing edge space for args without a leading auto space before `/`.

Generated send chunks use `generated-reference` provenance with strategy semantics. `delivery.ts` owns authored-only chunk aggregation, attachment deduplication by normalized server path or ID, exhaustive semantic partitioning, and Session and Skill synthetic delivery parts from the owner directory snapshot. `components/chat/chatComposerDelivery.ts` is the shared chat authored compiler for direct sends and queue dispatch; it resolves agent, file, skill, session-label, and citation delivery only in authored chunks. After prompt-attachment upload, `buildMessageParts` expands `[image-1.png]` citations to the durable host path so later agents can Read the file; sent-message chips map that path back to the short filename. Relay/slim still drops attachment bodies. Composer `@` file mentions stay plain query text until confirmation: autocomplete Enter/Tab, a terminating space, or a pasted path-like reference (`src/a.ts`, `src/foo/`). In-progress tokens such as `@yi.ts` are not highlighted and backspace deletes a character. Ranking prefers source paths over `test/`, files when the query has an extension, and directories when it ends with `/`. Inline `@` file mentions normalize with browser-safe `pathe` (`normalize` / `isAbsolute` / `join` / `basename`): Windows drive and UNC absolutes keep their own root (never project-joined) as `C:/...` or `//server/share/...`, relative mentions resolve under the session root (POSIX, drive, or UNC), and `file://` URLs encode drive letters as `file:///C:/...` with path-segment encoding. Composer citation decoration preserves image identity with the image icon while other attached files (documents, VS Code files, and code selections) use the attachment icon. Generated references and Paste payload chunks remain byte-for-byte opaque.

Queue edit, session revert, and sent-message edit share Composer restoration under `packages/ui/src/sync/`: `message-composer-restoration-sources.ts` builds complete `DraftSnapshot` + attachment values payloads (queue sidecars or authored message parts); `message-composer-restoration-cas.ts` owns capture/commit/rollback; `message-composer-restoration.ts` is a thin facade for existing imports. Invalid payloads fail before write; API failures roll back only when the restored revision is still current (`status=committed` and `current=true`). Prior draft absence rolls back through durable CAS `deleteDraftSnapshot` (tombstone + metadata delete) so memory returns to true absence rather than an empty snapshot. Cross-runtime or stale-runtime rollback ends after one best-effort attempt. Queue bridges still gate queue remove on `draft.durable` (durable-before-remove). Surface attachment CRUD uses `draft-attachment-resource-adapter.ts` with an explicit DraftKey (not `activeAttachmentDraft`). Root replacement is a single input-store CAS (`replaceDraftRootAttachments`) serialized per draft key so multi-step fire-and-forget clear/restore cannot interleave.

Queue admission stores `content` as the queue-canonical projection and an optional `composerDocument` sidecar as the authoritative semantic body. Strict parsing requires queue-canonical sidecar serialization to equal `content`; a sidecar's visible `text` may retain compact Paste labels or Session labels. Legacy rows use text-only delivery. `describeComposerDocumentResources()` defines sidecar attachment identities, which form a subset of queue attachments; independent attachments remain valid queue resources.

Queued Composer documents may carry `composerMentions`, a bounded authored file/agent identity sidecar. It retains confirmed file identity across queueing, recovery, edits, and durable delivery. The controller creates a stable range order before commit, while strict Draft and Queue parsers reject overlap, token drift, and reference-range collisions. Skill and image behavior remains owned by Composer reference strategies.

Project-scoped new-session drafts (`new-session:project:…` / directory / default) reuse a stable `draftID` so close + same-project reopen restores the complete durable `DraftRecord`: visible text, all Composer reference sidecars (`session` / `paste` / `skill` / `command`), file/directory/agent mentions, root and synthetic attachment metadata, and synthetic parts. Different projects keep isolated keys. ChatInput agent chip selection writes a durable `DraftMention` with `kind: 'agent'` whose range covers only the exact `@agentName` token (boundary spaces from `insertTokenWithReferenceBoundaries` are excluded); existing mentions are rebased and deduped by kind/value/range the same way as file/directory mentions.
